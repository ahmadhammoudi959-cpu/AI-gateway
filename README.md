# بوابة الذكاء — منصة توزيع مفاتيح الذكاء الاصطناعي على تطبيقاتكم

منصة واحدة تشترون لها مفاتيح الـ API من Anthropic وOpenAI وغيرهما، وكل تطبيق تبنونه (Star Style، GoTrend، …) يأخذ منها **مفتاحاً خاصاً به وحداً شهرياً حسب باقته**. لما التطبيق يخلّص حده يتوقف تلقائياً لحد ما ترقّوا باقته أو تشحنوا له رصيد — وأنتم شايفين في لوحة واحدة كل تطبيق صرف كام، دفع كام، وربحكم منه كام.

```
  Star Style ──┐                                ┌──► Anthropic (Claude)
  GoTrend   ───┤   sk-gw-…  ┌───────────────┐   ├──► OpenAI
  New app   ───┼──────────► │  AI Gateway   │ ──┼──► Google Gemini
  …         ───┘            │ key per app   │   └──► DeepSeek / OpenRouter / …
                            │ monthly limit │
                            │ usage + bills │
                            └───────────────┘
```

- مفاتيح المزوّدين الحقيقية تبقى **مشفّرة داخل المنصة فقط** — لا يراها أي تطبيق.
- التطبيق يغيّر **متغيرين فقط** (`ANTHROPIC_API_KEY` و`ANTHROPIC_BASE_URL`) بدون تعديل الكود غالباً.
- لوحة تحكم عربية: عدادات الاستهلاك، الباقات، المالية (تحصيل − تكلفة = ربح)، سجل كل طلب، وتنبيهات تيليجرام.
- صفحة للعميل يشوف فيها استهلاكه ويطلب الترقية بواتساب.

## التشغيل على Render

`render.yaml` يجهّز كل شيء تلقائياً: السيرفر (خطة مجانية) + قاعدة بيانات Postgres خاصة على Render بأقل خطة مدفوعة (`0.1c-256mb`)، الاثنان في Frankfurt (الأقرب لمصر والشام).

### 1) المشروع على GitHub
المجلد فيه مستودع git جاهز. أنشئ مستودعاً خاصاً (Private) فارغاً على GitHub ثم:
```bash
cd ai-gateway
git remote add origin https://github.com/<حسابك>/ai-gateway.git
git push -u origin main
```

### 2) Render
1. **New ← Blueprint** واختر المستودع. سيقرأ `render.yaml` ويعرض: قاعدة البيانات `ai-gateway-db` والسيرفر `ai-gateway`، مع السعر الشهري المتوقع قبل التأكيد.
2. سيطلب قيمتين:
   - `ADMIN_EMAIL` — بريد حساب المدير.
   - `ADMIN_PASSWORD` — كلمة مرور قوية (8 أحرف على الأقل).

   رابط قاعدة البيانات يُربط تلقائياً، و`ENCRYPTION_KEY` و`SESSION_SECRET` يولّدهما Render.
3. اضغط **Deploy Blueprint** وانتظر حالة **Live** للخدمتين.
4. افتح رابط الخدمة مضافاً إليه `/admin` — مثل `https://ai-gateway-xxxx.onrender.com/admin` — وسجّل الدخول.
5. **مهم:** من تبويب Environment في الخدمة انسخ قيمة `ENCRYPTION_KEY` واحفظها في مكان آمن. لو اتغيرت، مفاتيح المزوّدين المحفوظة لن تُقرأ ويلزم إدخالها من جديد.

> **عن الخطط:**
> - قاعدة البيانات مدفوعة (أقل خطة) لأن Render يسمح بقاعدة مجانية واحدة فقط لكل حساب، وتُحذف بعد 30 يوماً.
> - السيرفر على الخطة المجانية: "ينام" بعد 15 دقيقة بدون طلبات، وأول طلب بعدها ينتظر حوالي دقيقة. للتشغيل الفعلي مع العملاء غيّر `plan: free` للسيرفر في `render.yaml` إلى خطة مدفوعة مثل `0.5c-512mb`.

**نطاق خاص (اختياري):** من إعدادات الخدمة في Render أضف Custom Domain مثل `ai.yourcompany.com`، ثم من لوحة التحكم ← الإعدادات ← «رابط المنصة العام» اكتب الرابط الجديد حتى يظهر في متغيرات الربط.

**قاعدة بيانات أخرى:** أي Postgres يعمل (مثل Neon المجاني أو Supabase أو سيرفركم): احذف قسم `databases` من `render.yaml` واجعل `DATABASE_URL` قيمة تُدخلها يدوياً (`sync: false`). الاتصال المشفّر (SSL) يُفعَّل تلقائياً للعناوين الخارجية، ويمكن فرضه أو إيقافه بـ `DATABASE_SSL=true/false`.

## تفعيل النظام لأول مرة

لوحة التحكم تعرض هذه الخطوات في الصفحة الرئيسية لحد ما تكتمل.

### 1) أضف مفتاح المزوّد
**المزوّدون ← إضافة مزوّد ← Anthropic** والصق المفتاح من [console.anthropic.com](https://console.anthropic.com/settings/keys) (Settings ← API Keys ← Create Key).
المنصة تختبر المفتاح فوراً وتعرض قائمة الموديلات المتاحة له.

مدعوم أيضاً: OpenAI، Google Gemini، DeepSeek، OpenRouter، Groq، xAI، Mistral، Together، وأي خادم متوافق مع OpenAI (مثل Ollama أو vLLM).

### 2) فعّل الموديلات
اختر من القائمة الموديلات التي تستخدمها تطبيقاتكم. **الأسعار المرجعية تُملأ تلقائياً** (بالدولار لكل مليون توكن — تكلفتكم عند المزوّد) ويمكن تعديلها من «الموديلات والأسعار». راجعها مع صفحة أسعار المزوّد، فالأسعار تتغير.

اترك «الاسم الذي تستخدمه التطبيقات» مطابقاً لاسم الموديل عند المزوّد (مثل `claude-sonnet-5-5`) حتى لا تحتاج التطبيقات أي تعديل.

### 3) أنشئ الباقات
الباقة = **سعر شهري يدفعه العميل** + **حد لتكلفة الاستهلاك الفعلية**. الفرق بينهما هو أقل ربح مضمون:

| الباقة | سعر الاشتراك | حد الاستهلاك | أقل ربح مضمون |
|---|---|---|---|
| أساسية | $15 | $10 | $5 |
| احترافية | $30 | $20 | $10 |
| أعمال | $50 | $35 | $15 |

ويمكن لكل باقة تحديد الموديلات المسموحة (مثلاً الأرخص فقط) وحد طلبات في الدقيقة.

### 4) أضف التطبيق وانسخ متغيراته
**التطبيقات ← إضافة تطبيق** ← الاسم (Star Style) والباقة ← تظهر لك نافذة فيها:

```env
ANTHROPIC_API_KEY=sk-gw-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
ANTHROPIC_BASE_URL=https://ai-gateway-xxxx.onrender.com
```

المفتاح الكامل يظهر **مرة واحدة فقط** (المنصة تحفظ بصمته المشفّرة لا المفتاح نفسه). لو ضاع: صفحة التطبيق ← «مفتاح جديد».

### 5) حدّث التطبيق
في Render الخاص بتطبيق Star Style: **Environment** ← غيّر قيمة `ANTHROPIC_API_KEY` للمفتاح الجديد وأضف `ANTHROPIC_BASE_URL` ← Save. Render يعيد تشغيل التطبيق، ومن تلك اللحظة كل طلبات الذكاء الاصطناعي تمر عبر المنصة وتُحسب على باقته.

جرّب ميزة الذكاء الاصطناعي في التطبيق، وسيظهر الطلب خلال ثوانٍ في صفحة التطبيق ← «آخر الطلبات».

## ربط تطبيق (للمطوّر)

### تطبيقات تستخدم مكتبة Anthropic الرسمية
مكتبات Anthropic (Node/TypeScript وPython) تقرأ `ANTHROPIC_API_KEY` و`ANTHROPIC_BASE_URL` من البيئة تلقائياً، فالكود يبقى كما هو:

```js
// npm install @anthropic-ai/sdk
import Anthropic from '@anthropic-ai/sdk';
const client = new Anthropic(); // يقرأ المتغيرين من البيئة
const msg = await client.messages.create({
  model: 'claude-sonnet-5-5',
  max_tokens: 1024,
  messages: [{ role: 'user', content: 'اقترح تنسيقاً لقميص أزرق' }],
});
```

```python
import anthropic
client = anthropic.Anthropic()  # reads ANTHROPIC_API_KEY and ANTHROPIC_BASE_URL
msg = client.messages.create(model="claude-sonnet-5-5", max_tokens=1024,
                             messages=[{"role": "user", "content": "مرحبا"}])
```

البث (streaming)، الأدوات (tools)، الصور، الـ prompt caching، و`count_tokens` كلها تمر كما هي. هيدر `anthropic-beta` يُمرَّر أيضاً.

**أسماء الموديلات:** التطبيق يستمر في استخدام نفس الاسم. المنصة تتعرف على الأسماء بتاريخ (`claude-sonnet-4-5-20250929` = `claude-sonnet-4-5`) وعلى معرّف المزوّد حتى لو اخترت اسماً مختلفاً للموديل.

### تطبيقات تستخدم OpenAI أو مكتبة متوافقة
```env
OPENAI_API_KEY=sk-gw-...
OPENAI_BASE_URL=https://ai-gateway-xxxx.onrender.com/v1
```
نفس المفتاح يشغّل كل موديلات الباقة عبر `/v1/chat/completions` — بما فيها Claude (المنصة تترجم الطلب والرد والبث والأدوات تلقائياً). مدعوم أيضاً `/v1/responses` و`/v1/embeddings` و`/v1/images/generations` لموديلات المزوّدين المتوافقين مع OpenAI.

### طلب HTTP مباشر (PHP / Laravel مثلاً)
لو الكود يكتب الرابط `https://api.anthropic.com` بنفسه، استبدله بالمتغير:

```php
$response = Http::withHeaders([
    'x-api-key' => env('ANTHROPIC_API_KEY'),
    'anthropic-version' => '2023-06-01',
])->post(rtrim(env('ANTHROPIC_BASE_URL'), '/') . '/v1/messages', [
    'model' => 'claude-sonnet-5-5',
    'max_tokens' => 1024,
    'messages' => [['role' => 'user', 'content' => 'مرحبا']],
]);
```

بعض المكتبات (مثل Vercel AI SDK) تطلب رابطاً ينتهي بـ `/v1` — استخدم `https://…onrender.com/v1` لها.

### ماذا يرى التطبيق عند انتهاء الرصيد؟
الطلب يُرفض قبل أن يكلّفكم شيئاً، برسالة عربية/إنجليزية ورقم التواصل من الإعدادات:

| الحالة | HTTP | `error.code` |
|---|---|---|
| وصل للحد الشهري | 402 | `budget_exceeded` |
| الاشتراك منتهي (بدون تجديد تلقائي) | 402 | `subscription_expired` |
| بدون باقة | 402 | `no_active_plan` |
| التطبيق موقوف يدوياً | 403 | `system_suspended` |
| الموديل خارج الباقة | 403 | `model_not_allowed` |
| موديل غير موجود | 404 | `model_not_found` |
| تجاوز حد الطلبات في الدقيقة | 429 | `rate_limit_exceeded` (+ `Retry-After`) |
| مفتاح خاطئ أو ملغى | 401 | `invalid_api_key` |

اعرض للمستخدم رسالة لطيفة بدل الخطأ التقني:

```js
try {
  const msg = await client.messages.create({ /* … */ });
} catch (err) {
  if (err.status === 402) return showBanner('خدمة الذكاء الاصطناعي متوقفة مؤقتاً — تواصل مع الإدارة');
  throw err;
}
```

### معرفة الرصيد من داخل التطبيق
`GET /v1/usage` بنفس المفتاح يرجع الباقة ونسبة الاستهلاك وأيام الدورة المتبقية — مفيد لعرض «استهلكت 62% من باقتك» داخل التطبيق. المبالغ بالدولار لا تظهر إلا إذا فعّلتها من الإعدادات.

### إشعارات للتطبيق (اختياري)
في «تعديل التطبيق» ضع رابط Webhook، وتصله رسالة `POST` بصيغة JSON:
- `usage.threshold` عند نسبة التنبيه (80% افتراضياً) وعند 100%
- `subscription.expiring` قبل انتهاء الاشتراك بثلاثة أيام (لو التجديد التلقائي مقفول)
- `subscription.expired` عند الانتهاء

## كيف يُحسب الاستهلاك والباقات

- **تكلفة الطلب** = توكنز الدخل والخرج كما يرسلها المزوّد × سعر الموديل لكل مليون توكن. توكنز الكاش تُحسب بسعر الكاش، وكتابة الكاش في Claude بسعرها، والموديلات ذات السعر الأعلى للسياق الطويل (مثل Gemini Pro فوق 200 ألف توكن، Claude Haiku 5.5 فوق 100 ألف) تُحسب بالسعر الأعلى.
- **البث المقطوع:** لو التطبيق قطع الاتصال أثناء البث، يُحسب ما تم توليده فعلاً بتقدير (يظهر «تقديري» في السجل). الطلبات العادية (بدون بث) تكتمل دائماً لتُحسب بدقة.
- **العداد** يمتلئ بالتكلفة الفعلية؛ عند 100% تُرفض الطلبات الجديدة. الطلبات التي كانت قيد التنفيذ لحظة الوصول للحد تكتمل، لذلك قد يتجاوز العداد الحد قليلاً بقيمة تلك الطلبات. لتقليل ذلك تحجز المنصة لكل طلب جارٍ تكلفة متوقعة (من حجم الطلب ومتوسط تكلفة الموديل الفعلية).
- **الشهر** يبدأ من تاريخ إضافة التطبيق (أو آخر تجديد) وليس أول الشهر الميلادي.
- **تجديد تلقائي (افتراضي):** عند نهاية الشهر يبدأ شهر جديد ويتصفّر العداد. مناسب لتطبيقاتكم الداخلية والعملاء بالدفع الشهري.
- **بدون تجديد تلقائي:** يتوقف التطبيق عند نهاية الشهر حتى تضغط «تجديد» (ويصلكم تنبيه قبلها بثلاثة أيام).
- **ترقية الباقة:** اختيارياً تبدأ شهراً جديداً من اليوم بحد الباقة الجديدة كاملاً (الافتراضي)، أو ترفع الحد فوراً على الشهر الحالي.
- **شحن رصيد:** يضيف مبلغاً لحد الشهر الحالي فقط (يُصفّر مع الشهر الجديد). المنصة تقترح الرصيد بنفس نسبة باقة العميل.
- **التحصيل:** المبالغ التي تسجلها عند الإضافة أو التجديد أو الترقية أو الشحن، أو من «المالية ← تسجيل دفعة». الربح = التحصيل − تكلفة الاستهلاك.
- **موديل بديل:** لكل موديل يمكن تحديد بديل يُستخدم تلقائياً لو المزوّد تعطّل أو رفض المفتاح، ويُسجَّل ذلك في السجل.

## التنبيهات وصفحة العميل

**تيليجرام:** الإعدادات ← التنبيهات. أنشئ بوتاً من [@BotFather](https://t.me/BotFather) وانسخ التوكن، ثم أرسل أي رسالة للبوت واعرف رقم المحادثة (Chat ID) من [@userinfobot](https://t.me/userinfobot) — أو أضف البوت لمجموعة الفريق واستخدم رقمها. اضغط «إرسال رسالة تجربة». تصلكم رسالة عند:
- وصول تطبيق لنسبة التنبيه (80%) ثم للحد
- اقتراب انتهاء اشتراك بدون تجديد تلقائي، وعند انتهائه
- رفض مزوّد لمفتاح الـ API (مثلاً انتهى رصيدكم عند Anthropic)

**صفحة العميل:** `https://<المنصة>/portal` — صاحب التطبيق يدخل مفتاحه ويرى نسبة استهلاكه، أيام الشهر المتبقية، الاستهلاك اليومي، والباقات المتاحة مع زر «طلب ترقية عبر واتساب» (يستخدم رقم التواصل من الإعدادات). افتراضياً تظهر النسب فقط بدون مبالغ حتى لا تظهر تكلفتكم الفعلية.

## التشغيل على سيرفر خاص أو محلياً

### سيرفر خاص (VPS) بـ Docker
يحتاج Docker ونطاقاً يشير لعنوان السيرفر:

```bash
cp .env.example .env      # عدّل القيم: ENCRYPTION_KEY, SESSION_SECRET, ADMIN_*, POSTGRES_PASSWORD, DOMAIN
docker compose up -d --build
```
يشغّل المنصة + Postgres + Caddy (شهادة HTTPS تلقائية). اللوحة على `https://DOMAIN/admin`.

### محلياً للتطوير (بدون تثبيت قاعدة بيانات)
يحتاج Node.js 20.10 أو أحدث:
```bash
npm install
npm run seed:demo   # اختياري: بيانات تجريبية (7 تطبيقات، 5 أشهر استهلاك) بمفاتيح وهمية
npm start           # http://localhost:3000/admin
```
بدون `DATABASE_URL` تعمل المنصة بقاعدة Postgres مدمجة (PGlite) في مجلد `data/`. عند أول تشغيل بدون `ADMIN_EMAIL`/`ADMIN_PASSWORD` يُطبع في السجل حساب `admin@local` بكلمة مرور عشوائية.

### نسيت كلمة المرور؟
```bash
node src/cli.js reset-password you@example.com new-password-123
```
(على Render: من Shell الخدمة.)

## الأمان والنسخ الاحتياطي

- مفاتيح المزوّدين مشفّرة بـ AES-256-GCM بالمفتاح `ENCRYPTION_KEY`، ولا تُرسل للمتصفح أبداً (تظهر آخر 4 أحرف فقط).
- مفاتيح التطبيقات تُحفظ كبصمة SHA-256 فقط، فتسريب قاعدة البيانات لا يكشفها.
- أي رسالة خطأ من المزوّد تُنظَّف من المفاتيح قبل وصولها للتطبيق، وأخطاء رفض المفتاح لا تُعرض للتطبيق إطلاقاً.
- لوحة التحكم: جلسات موقّعة (HttpOnly + SameSite=Strict)، حماية من محاولات الدخول المتكررة، ورفض الطلبات من مواقع أخرى.
- محتوى المحادثات **لا يُحفظ** — السجل يحفظ بيانات الطلب فقط (الموديل، التوكنز، التكلفة، المدة، النتيجة).
- **النسخ الاحتياطي:** على Render، قواعد البيانات المدفوعة لها نسخ احتياطية تلقائية (راجع إعدادات القاعدة). احتفظ أيضاً بنسخة من `ENCRYPTION_KEY`.
- مدة حفظ سجل الطلبات قابلة للتعديل (90 يوماً افتراضياً)؛ الملخصات اليومية والمالية تبقى دائماً.

## مرجع الـ API

كل الطلبات بمفتاح التطبيق في `Authorization: Bearer sk-gw-…` أو `x-api-key: sk-gw-…`.

| المسار | الوصف |
|---|---|
| `POST /v1/messages` | Anthropic Messages كما هو (للتطبيقات التي تستخدم مكتبة Anthropic) |
| `POST /v1/messages/count_tokens` | عدّ التوكنز — مجاني |
| `POST /v1/chat/completions` | صيغة OpenAI لكل الموديلات (بما فيها Claude) مع البث والأدوات |
| `POST /v1/responses` | OpenAI Responses API (موديلات المزوّدين المتوافقين مع OpenAI) |
| `POST /v1/embeddings` | Embeddings |
| `POST /v1/images/generations` | توليد صور (يُحسب بالتوكنز أو بسعر ثابت للصورة) |
| `GET /v1/models` | الموديلات المتاحة لباقة التطبيق (بصيغة Anthropic لو أُرسل `anthropic-version`) |
| `GET /v1/usage` | الباقة ونسبة الاستهلاك والأيام المتبقية |
| `GET /healthz` | فحص صحة السيرفر وقاعدة البيانات |

كل رد يحمل `x-request-id` — نفس الرقم يظهر في سجل الطلبات للبحث عن أي مشكلة.

## مشاكل شائعة

**التطبيق يرجع 401 `invalid_api_key`** — المفتاح منسوخ ناقصاً أو أُلغي. أنشئ مفتاحاً جديداً من صفحة التطبيق.

**404 `model_not_found`** — اسم الموديل في كود التطبيق غير مفعّل في «الموديلات والأسعار». أضفه بنفس الاسم، أو افتح `GET /v1/models` لترى المتاح.

**502 `upstream_auth_error`** — المزوّد رفض مفتاحكم (انتهى الرصيد عند المزوّد أو أُلغي المفتاح). يصلكم تنبيه، واختبر المفتاح من صفحة المزوّدين.

**الطلبات لا تظهر في السجل** — التطبيق ما زال يستخدم `api.anthropic.com`. تأكد من `ANTHROPIC_BASE_URL` وأعد تشغيل التطبيق.

**«تعذر فك تشفير المفتاح»** — تغيّر `ENCRYPTION_KEY`. أعد قيمته القديمة، أو أعد إدخال مفاتيح المزوّدين.
